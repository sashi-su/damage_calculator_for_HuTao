## 表示文章の編集

ページの主要な表示文章は `content.js` にまとめています。`page` の中はページのセクション順、`forms` の中は入力画面の種類とキャラクターごとに整理されています。

- 見出しや説明文は、対応する名前の文字列を書き換えます。
- 前提条件・プリセット・参考リンク・更新履歴・入力項目など、繰り返し表示される内容は配列です。項目の追加・削除・並べ替えも配列内で行えます。
- `id`、`value`、`url`、画像の `image` は動作や参照先に使う値です。文章だけを変更するときは、主に `title`、`label`、`note`、`hint`、`text`、`name` を編集してください。
- 各キャラクターの参考値は `page.referenceValues`、ダメージ分析内の文章は `page.sections.analysis.content` で編集できます。
- 確認時の状態の見出し・セグメント選択肢の項目名・ポップアップは `forms.interface.inputModes`、選択肢の文言は各入力項目の `options`、計算過程の文章は `page.sections.verification.content` で編集できます。
- HTMLタグを含む `rotation.formula` を除き、通常の文章にHTMLを書く必要はありません。

UIの編集・要素追加時は、[UIデザイン方針](UI_DESIGN.md)を参照してください。通常のカードは基本・内側・結果の3種類を使い、「合計ダメージ期待値」だけ専用の濃い赤のカードを使います。編集エージェント向けの指示は [AGENTS.md](AGENTS.md) にあります。

`index.html` をブラウザーで開いて使用できます。HTML / CSS / JavaScriptだけで動作し、サーバーやインストールは不要です。

更新履歴はwebサイト完成後の更新時にのみ追記し、完成までの通常編集では追記しない。

画面は「基本設定」「胡桃の設定」「サポーターの設定」「計算過程」「ダメージ分析」「その他」の6つに分かれています。「計算過程」では、護摩と元素スキル適用後の胡桃、編成した最大3人のサポーター、カスタムバフ、元素共鳴などによる増減と最終値を、ステータス・ダメージ補正・防御無視・敵元素耐性の一覧表および攻撃力・ダメージの計算式で確認できます。表のダメージバフは小数第一位、その他の項目は整数で表示します。

## 画面固有の表示仕様

- 基本設定は、固定ローテーションの下に元素反応設定、敵の設定、カスタムバフを順に表示します。各区分は見出しと区切り線で分け、追加のカードは作りません。カスタムバフの説明は詳細を閉じた状態でも表示します。
- 「攻撃力%を含める」は、伸びしろと理想スコアの両方に置くチェックボックスです。有効時は、攻撃力%をHP%と元素熟知の間に表示します。
- モバイルの最終ステータス計算は、デスクトップ表と同じ値をステータス選択と縦型の寄与一覧で表示します。
- モバイルのダメージ記録・比較表には、ラベル、増加率、合計ダメージ期待値、基準、削除を表示し、増加幅は隠します。ラベル欄を広く取り、必要な場合は表内を横スクロールできるようにします。保存データとデスクトップ表の内容は維持します。

## 採用した仕様

damage_formula.md を基礎に、固定ローテーションは通常1段目・重撃各10回、血梅香2回、元素爆発0.5回とします。血梅香は元素スキル中の攻撃力を参照し、2凸以上では各回にHP上限×10%を加算します。合計ダメージ期待値では集約した見かけの元素反応確率・倍率を使い、個別攻撃のICDや付着、バフ時間推移、味方の攻撃はシミュレーションしません。「ダメージ分析」の実ダメージ確認では、攻撃1回ごとに会心・反応・実数加算、夜蘭の経過時間、ニコのバフを選択できます。

HP50%未満、護摩Lv.90、炎杯、魔女4セット1層が固定です。通常天賦はLv.10。元素スキル天賦は0〜2凸でLv.10、3凸以降でLv.13、元素爆発天賦は0〜4凸でLv.10、5凸以降でLv.13として命ノ星座から自動設定します。ニコの元素スキル天賦は0〜2凸でLv.10、3凸以降でLv.13として自動設定します。

胡桃のHP上限と攻撃力は確認した数値を入力し、その数値を確認した時点の条件を指定します。HP上限では水共鳴、攻撃力では水・炎共鳴とHP50%未満かどうかを選びます。ページは共鳴なし・HP50%以上の値への換算値を表示し、これを基準に現在の編成でのダメージを計算します。初期状態では換算値と「○○の設定」だけを表示し、展開すると確認した数値と確認時の条件を編集できます。編成を変更しても入力値と確認時の条件は維持します。元素スキルと味方の一時的なバフは入力値に含めません。胡桃設定の参考値には、基礎HP・基礎攻撃力、護摩のHP条件別の攻撃力バフ、元素スキルの攻撃力バフ、炎元素ダメージバフ、実効会心率を表示します。

胡桃6凸では効果発動割合pを0〜100%で入力し、装備後の基準会心率をrとして、実効会心率を `p + (1 - p)r` で計算する。内部ではpとrを0〜1へ変換し、基準会心率は100%を上限とする。6凸未満ではp=0として扱う。

合計ダメージ期待値では、夜蘭の元素爆発による平均ダメージバフと4凸層数を入力します。発動回数・効果の順序を入力するものはその設定で計算し、編成・命ノ星座・装備の条件を満たす効果をローテーション全体に適用します。夜蘭4凸は0〜4層を指定し、1層につき対象キャラクターの基礎HPの10%を加算します（初期値4層）。シトラリ6凸は最大40カウントのダメージバフ60%、フリーナは最大テンション、ニコは昇格済みとして計算します。フリーナの元素爆発天賦は0〜2凸でLv.10、3凸以降でLv.13として自動設定します。武器のチェックは装備と効果発動済みを兼ね、シトラリとシロネンの聖遺物は英雄の絵巻4・教官4・効果なしから選択します。

シトラリの元素熟知は、確認した数値に2凸効果の125を含むかを指定し、含む場合は差し引いて換算します。フリーナのHP上限とニコの攻撃力も、確認時の水・炎共鳴の有無をそれぞれ指定して換算します。シトラリの数値には武器・聖遺物のステータス・教官2セットを含め、終焉・聖顕・教官4・味方バフは含めません。星の刃は0〜16回。シトラリの教官4は胡桃と星の刃が参照するシトラリの双方に元素熟知120を加えます。聖顕の鍵は、設定に応じて選択中のフリーナのレベルに対応する基礎HP、水共鳴、夜蘭4凸、シロネン2凸、チーム全員に有効なカスタムHPを参照します。ニコは基礎攻撃力を別入力し、設定に応じて終焉やシロネン2凸の攻撃力%を元素スキル効果の計算前または後に加えます。ニコの参考値では、元素スキル効果の計算前の攻撃力と、聖祝の導きおよび必要な後発の効果を加えた最終攻撃力を表示します。

シロネンは編成に対象元素の味方がいる場合に炎耐性低下を与え、2凸では攻撃力%も加えます。4凸効果の実数ダメージ加算は6回分として計算し、武器「岩峰を巡る歌」のダメージバフは防御力に応じて上限まで適用します。シトラリと同じ聖遺物セットを選んだ場合、英雄の絵巻4・教官4の効果は重複しません。

カスタム設定では、HP%、攻撃力固定値、攻撃力%、元素熟知、会心率、会心ダメージ、共通ダメージバフ、元素反応の加算効果、実数ダメージ加算、防御デバフ、防御無視、元素耐性デバフを胡桃へ反映します。「チーム全員に有効」を選んだHP%は聖顕の鍵が参照するフリーナのHP、攻撃力固定値・攻撃力%はニコの参照攻撃力、元素熟知はシトラリ1凸の参照熟知にも反映します。

防御デバフと元素耐性デバフは、低下量を負数で入力する。たとえば20%低下は `-20` と入力する。

入力例は「夜蘭・ニコ・シトラリ用」プリセットと同じ見かけの元素反応確率74.86%、倍率1.701です。入力値はブラウザーのローカルストレージへ自動保存します。「ダメージ分析」では合計ダメージ期待値を名前付きで最大30件保存し、基準との差、増加率、棒グラフを比較できます。保存した記録、基準、入力途中の記録名、伸びしろ・理想スコアの設定も同じブラウザーに保存します。「その他」では、入力内容、登録済みの聖遺物、ダメージ比較記録、DPS設定を1行の設定コードとして表示・コピーし、別のブラウザーで復元できます。新コードは形式バージョン4で、gzipを使わず、配列・1/0・初期値の省略で短縮します。形式バージョン1〜3も変換して読み込めます。比較基準、伸びしろ・理想スコアの設定は設定コードに含めません。「その他」ではステータス更新の提案・促しの設定も変更できます。保存形式と固定の対応表は [settings_code_specification.md](settings_code_specification.md) を参照してください。

反応プリセットは「夜蘭・行秋・鐘離用」（p=0.8360、a=1.5）、「夜蘭・ニコ・シトラリ用」（p=0.7486、a=1.701）、「夜蘭・フリーナ・シトラリ用」（p=0.7586、a=1.744）です。画面のp入力欄は百分率表示のため、それぞれ83.60%、74.86%、75.86%として設定します。これらは制作者の実測値であり、プレイスキルや凸状況によって変化します。

## 計算処理と表示の分担

「聖遺物最適化」では★5・Lv.20の聖遺物を各部位10個まで登録できます。各部位から1個ずつ選び、火魔女4セットを満たす組み合わせだけを、現在のキャラクター・装備・基本設定・サポーター設定で計算します。上位3位以内を同点も含め最大10件表示し、装備後ステータスを胡桃の設定へ反映できます。登録一覧・順序・ID・採番情報は通常設定とは別のローカルストレージへ保存し、入力例へのリセットでも維持します。入力途中の内容とランキングは保存しません。

杯の選択は通常設定・設定コードへ含め、項目のない旧設定コードでは炎元素ダメージバフを適用します。新設定コードは聖遺物一覧・順序・ID・採番情報も復元し、旧コードでは現在の聖遺物を維持します。通常の設定変更・聖遺物の変更ではランキングを消去し、ランキングから設定欄への反映では維持します。詳細は [artifact_optimizer_specification.md](artifact_optimizer_specification.md) を参照してください。

- calculator.js が数値計算を担当し、最終値と途中値、発生源別の contributions を返す。効果の加算は同時に内訳へ記録し、一覧表でキャラクターの条件式を再実装しない。
- attack-trace.js と damage-trace.js は計算結果を説明文・数式に整形する。反応補正の途中値、補正前の合計も計算本体から受け取る。
- 固定ローテーションは rotation にまとめ、総天賦倍率・攻撃別内訳・基本設定の参考式で共有する。
- 合計ダメージ期待値は変更を確定する change 通知で再計算し、入力途中の input 通知では再計算しない。スライダーの値表示は操作中も更新する。確定済みの生の値が変わらない通知では計算・保存・再描画を繰り返さず、空欄と数値0は区別する。
- referenceHp / referenceAtk は外部バフの適用範囲が異なる参考値であり、最終ステータスとは別に計算する必要がある。
- 既存の結果出力フィールドは維持する。effects のニコの値はニコ単独の寄与とし、カスタム固定攻撃力を重ねて含めない。

## 検証範囲

- `node test-styles.cjs`：デザイントークン、共通色の直書き防止、CSSの括弧・コメント構造を確認。
- `node test.cjs`：139項目の数値チェック。
- `node test-attack-trace.cjs`：護摩・元素スキル・カスタムHPを含む攻撃力計算過程の表示確認。
- `node test-damage-trace.cjs`：ダメージを構成する5要素、反応・耐性・6凸などの表示確認。
- `node test-damage-analysis.cjs`：伸びしろ、HP上限、実ダメージ、簡易DPS、ダメージ記録比較の確認。
- `node test-settings-transfer.cjs`：配列・1/0・初期値省略、数値の精度、25/50個の聖遺物・ID・順序、旧コード変換、不正データ、確認キャンセル・復元操作、25個での文字数を検証。
- `node test-artifact-optimizer.cjs`：全メインステータス、入力検証、護摩・スキル・共鳴、セット条件、同点順位、10万通りの探索、ID・保存・丸め、旧設定コードと非同期処理を確認。
- `node test-refactor.cjs`：1,000条件で内訳と合計の一致、反応・耐性・上限、入力重複と空欄からの復帰を確認。変更前の `calculator.js` の絶対パスを引数に渡すと、旧実装との比較も実行できます（同じ `data.js` を参照させます）。
