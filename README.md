# Hu_Tao_damage_calculator

# 胡桃用ダメージ計算機

## Webページの構成ファイル

`index.html` が次のCSS・JavaScriptを読み込み、JavaScriptが `images` 内の画像を参照してページを構成します。

## 表示文章の編集

ページの主要な表示文章は `content.js` にまとめています。`page` の中はページのセクション順、`forms` の中は入力画面の種類とキャラクターごとに整理されています。

- 見出しや説明文は、対応する名前の文字列を書き換えます。
- 前提条件・プリセット・参考リンク・更新履歴・入力項目など、繰り返し表示される内容は配列です。項目の追加・削除・並べ替えも配列内で行えます。
- `id`、`value`、`url`、画像の `image` は動作や参照先に使う値です。文章だけを変更するときは、主に `title`、`label`、`note`、`hint`、`text`、`name` を編集してください。
- 各キャラクターの参考値は `page.referenceValues`、ダメージ分析内の文章は `page.sections.analysis.content` で編集できます。
- 入力形式のポップアップは `forms.interface.inputModes`、計算過程の文章は `page.sections.verification.content` で編集できます。
- HTMLタグを含む `rotation.formula` を除き、通常の文章にHTMLを書く必要はありません。


更新履歴はwebサイト完成後の更新時にのみ追記し、完成までの通常編集では追記しない。

画面は「基本設定」「胡桃の設定」「サポーターの設定」「計算過程」「ダメージ分析」「その他」の6つに分かれています。「計算過程」では、護摩と元素スキル適用後の胡桃、編成した最大3人のサポーター、カスタムバフ、元素共鳴などによる増減と最終値を、ステータス・ダメージ補正・防御無視・敵元素耐性の一覧表および攻撃力・ダメージの計算式で確認できます。表のダメージバフは小数第一位、その他の項目は整数で表示します。

## 採用した仕様

damage_formula.md を基礎に、固定ローテーションは通常1段目・重撃各10回、血梅香2回、元素爆発0.5回とします。血梅香は元素スキル中の攻撃力を参照し、2凸以上では各回にHP上限×10%を加算します。合計ダメージ期待値では集約した見かけの元素反応確率・倍率を使い、個別攻撃のICDや付着、バフ時間推移、味方の攻撃はシミュレーションしません。「ダメージ分析」の実ダメージ確認では、攻撃1回ごとに会心・反応・実数加算、夜蘭の経過時間、ニコのバフを選択できます。

HP50%未満、護摩Lv.90、炎杯、魔女4セット1層が固定です。通常天賦はLv.10。元素スキル天賦は0〜2凸でLv.10、3凸以降でLv.13、元素爆発天賦は0〜4凸でLv.10、5凸以降でLv.13として命ノ星座から自動設定します。ニコの元素スキル天賦は0〜2凸でLv.10、3凸以降でLv.13として自動設定します。

胡桃のHP上限と攻撃力は、それぞれ「フィールド上」と「ビルドカード上」の入力形式を選べます。フィールド上HPには水共鳴を含め、ビルドカード上HPには含めません。フィールド上攻撃力にはHP50%未満の護摩と水・炎共鳴を含め、ビルドカード上攻撃力にはHP50%以上の護摩を含めて共鳴を含めません。いずれも元素スキルと味方バフは入力値に含めず、選択した形式に応じて不足分だけを計算時に加算します。胡桃設定の参考値には、計算に用いるフィールド上HP上限と元素スキル後の攻撃力などを表示します。

胡桃6凸では効果発動割合pを0〜100%で入力し、装備後の基準会心率をrとして、実効会心率を `p + (1 - p)r` で計算する。内部ではpとrを0〜1へ変換し、基準会心率は100%を上限とする。6凸未満ではp=0として扱う。

合計ダメージ期待値では、夜蘭の元素爆発による平均ダメージバフと4凸層数を入力し、それ以外は編成・命ノ星座・装備の条件を満たす効果が最大量で全期間有効として扱います。夜蘭4凸は0〜4層を指定し、1層につき対象キャラクターの基礎HPの10%を加算します（初期値4層）。シトラリ6凸は最大40カウントのダメージバフ60%、フリーナは最大テンション、ニコは昇格済みとして計算します。フリーナの元素爆発天賦は0〜2凸でLv.10、3凸以降でLv.13として自動設定します。武器のチェックは装備と効果発動済みを兼ね、シトラリの聖遺物は英雄の絵巻4・教官4・効果なしから選択します。

シトラリの元素熟知は「フィールド上」と「ビルドカード上」の入力形式を選べます。どちらも武器・聖遺物のステータス・教官2セットを含め、終焉・聖顕・教官4・味方バフは含めません。フィールド上熟知にはシトラリ2凸の125を含め、ビルドカード上熟知には含めません。星の刃は0〜16回。教官4は胡桃へ常に元素熟知120を加え、発動順の条件を満たす場合だけ星の刃が参照するシトラリの熟知にも加えます。聖顕の鍵は、設定に応じて選択中のフリーナのレベルに対応する基礎HP、水共鳴、夜蘭4凸、チーム全員に有効なカスタムHPを参照します。ニコは基礎攻撃力を別入力し、設定に応じて終焉の攻撃力%を元素スキル効果の計算前に加えます。

カスタム設定では、HP%、攻撃力固定値、攻撃力%、元素熟知、会心率、会心ダメージ、共通ダメージバフ、元素反応の加算効果、実数ダメージ加算、防御デバフ、防御無視、元素耐性デバフを胡桃へ反映します。「チーム全員に有効」を選んだHP%は聖顕の鍵が参照するフリーナのHP、攻撃力固定値・攻撃力%はニコの参照攻撃力、元素熟知はシトラリ1凸の参照熟知にも反映します。

防御デバフと元素耐性デバフは、低下量を負数で入力する。たとえば20%低下は `-20` と入力する。

入力例は「夜蘭・ニコ・シトラリ用」プリセットと同じ見かけの元素反応確率74.86%、倍率1.701です。入力値はブラウザーのローカルストレージへ自動保存します。「ダメージ分析」では合計ダメージ期待値を名前付きで最大30件保存し、基準との差、増加率、棒グラフを比較できます。保存した記録、基準、入力途中の記録名も同じブラウザーに保存します。

反応プリセットは「夜蘭・行秋・鐘離用」（p=0.8360、a=1.5）、「夜蘭・ニコ・シトラリ用」（p=0.7486、a=1.701）、「夜蘭・フリーナ・シトラリ用」（p=0.7586、a=1.744）です。画面のp入力欄は百分率表示のため、それぞれ83.60%、74.86%、75.86%として設定します。これらは制作者の実測値であり、プレイスキルや凸状況によって変化します。

## 計算処理と表示の分担

- calculator.js が数値計算を担当し、最終値と途中値、発生源別の contributions を返す。効果の加算は同時に内訳へ記録し、一覧表でキャラクターの条件式を再実装しない。
- attack-trace.js と damage-trace.js は計算結果を説明文・数式に整形する。反応補正の途中値、補正前の合計も計算本体から受け取る。
- 固定ローテーションは rotation にまとめ、総天賦倍率・攻撃別内訳・基本設定の参考式で共有する。
- 入力の生の値が変わらない input / change 通知では計算・保存・再描画を繰り返さない。空欄と数値0は区別する。
- referenceHp / referenceAtk は外部バフの適用範囲が異なる参考値であり、最終ステータスとは別に計算する必要がある。
- 既存の結果出力フィールドは維持する。effects のニコの値はニコ単独の寄与とし、カスタム固定攻撃力を重ねて含めない。

## 検証範囲

- `node test.cjs`：126項目の数値チェック。
- `node test-attack-trace.cjs`：護摩・元素スキル・カスタムHPを含む攻撃力計算過程の表示確認。
- `node test-damage-trace.cjs`：ダメージを構成する5要素、反応・耐性・6凸などの表示確認。
- `node test-damage-analysis.cjs`：伸びしろ、HP上限、実ダメージ、簡易DPS、ダメージ記録比較の確認。
- `node test-refactor.cjs`：1,000条件で内訳と合計の一致、反応・耐性・上限、入力重複と空欄からの復帰を確認。変更前の `calculator.js` の絶対パスを引数に渡すと、旧実装との比較も実行できます（同じ `data.js` を参照させます）。
